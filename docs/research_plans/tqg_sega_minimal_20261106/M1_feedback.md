# M1：同一个模型，先看方向，再试一次更新

[返回列表](README.md) · [共同协议](protocol.md) · 后续 [M2](M2_short_training.md)

**规模：2任务 × 3种子 × 4块 = 24个配对数据块；每块执行v1/v2，共48个版本块。全部只用新源模型θ0，不连续训练。**

白话：固定同一个人、同一道题，比较真实源标签、乱标签、平均标签和随机建议。先看建议是否指向正确方向，再看照着建议走一步，另一批目标图是否变好。

## 1. 先生成并固定查询，再看开发标签

每块固定fit16、query196、A16、B271。v1/v2共用图ID和快照；每版内部null必须复用它自己的查询。

| 版本 | 固定量 | 换标签时只改什么 |
|---|---|---|
| v1 | 探测方向、源/目标odd+even、共同RMS、源Gram和ridge | 用不同残差重算相关量及系数a，再算目标纠错和参数梯度 |
| v2 | V、源/目标A、H+A核、尺度、校准W | 替换源残差，计算 `g=-VWr`；W不能因换标签而变化 |

所有候选封存后，才读取开发A标签得到 `gA=∇CE_A`；B标签只用于评价和事后梯度诊断。fit/query都是源标签，仍按原角色使用。

## 2. 梯度对照

统一把g记为**损失梯度**，参数沿 `-g` 更新，不把“纠错方向”与“梯度方向”符号混用。

| 反馈 | 定义 | 用途 |
|---|---|---|
| TRUE | 各版本的原始反馈梯度 | 待检验方法 |
| PERM-1/2/3 | 源标签使用固定置乱映射；残差是 `置乱Y-p原图` | 是否需要真实的标签—图对应 |
| MEAN-Y | 残差 `barY-p_i` | 已知当前预测和类别比例能否解释效果 |
| RAND-1/2/3 | 同可执行空间高斯方向，缩放至TRUE范数 | 是否优于同样大小的无信息扰动 |
| QUERY-CE | query196的普通源CE梯度 `gq` | 直接使用同一批源标签是否已足够 |
| ORACLE-A | 真实开发A CE梯度；临时步中匹配TRUE范数 | 判断有监督方向是否能改善B |

v2的RAND空间是V。v1的RAND空间是 `U1=orth(C)`，其中第ℓ列 `Cℓ=mean_A(J_Aᵀ Ψ_A,ℓ)`，覆盖当前响应组合可执行的参数梯度；**不能直接把编码器探测v当作最终更新空间**，因为v1执行也会更新头。两版的RAND空间不同，报告中明确列出维数。

零空间/零TRUE时RAND为零，相关余弦为NA。PERM和MEAN-Y保留原幅度；记录范数差，不把其优劣全解释为方向差。Oracle只匹配范数，不用目标标签选择学习率或β。

主要记录：`cos(gTRUE,gA)`；TRUE对PERM均值、RAND均值的余弦优势；MEAN-Y对照；相对梯度误差；各反馈范数；β‖反馈‖/‖gfit‖；TRUE−MEAN-Y的中心化标签贡献。附报与B梯度的余弦及B梯度在各版可执行空间内的能量比例。

## 3. 独立临时单步

所有臂从同一θ0分别开始，`θ'=θ0-ηd`，η=0.0003、β=0.1。每次丢弃临时副本，原模型和BN buffer必须保持不变。

| 臂 | d |
|---|---|
| FROZEN | 0 |
| FIT-CE | gfit |
| FIT+QRY-CE | gfit + βgq |
| FIT+TRUE | gfit + βgTRUE |
| FIT+MEAN-Y | gfit + βgMEAN-Y |
| FIT+PERM-1/2/3 | gfit + βgPERM |
| FIT+RAND-1/2/3 | gfit + βgRAND |
| FIT+ORACLE | gfit + βnorm_match(gA) |
| TRUE-only | βgTRUE |
| ORACLE-only | βnorm_match(gA) |

每版13个非冻结临时步，共624个逻辑单步；两版共用的FIT-CE与FIT+QRY-CE可缓存，因此最多576次实际临时更新。它们不是576条独立训练轨迹。

每步在完整B271上计算普通NLL/CE，按图数加权，另报A的变化。主要增益：

`RTRUE = [L_B(FIT-CE) - L_B(FIT+TRUE)] / L_B(FROZEN)`。

同样计算TRUE相对MEAN-Y、PERM均值、RAND均值、FIT+QRY-CE的配对CE改善。比较一阶预测 `-η〈gB,d〉` 与真实有限步变化；Oracle-only/联合Oracle用于区分估计器问题与源目标冲突。

## 4. FP32下的小变化怎么判断

记录CE、参数和logit变化的绝对值，不能只报百分比。如果改善接近数值分辨率：

1. 将**已经固定的原参数与实际更新后参数**复制成FP64，只重算B损失；不重算V、核、W或方向。
2. 再比较“FP64理想步”和“FP32实际步转FP64”的差，定位参数写回舍入。
3. FP64检查只作误差审计，不替代主FP32实验，也不用它挑超参数。结果低于审计误差则记不可判定。

误差下限至少为 `10 * eps32 * max(1,L_B(FROZEN))`；若同一实际步的FP32/FP64损失差分不一致更大，使用该较大差异作为审计误差。单步正改善需超过此误差；否则不计种子胜利。

## 5. 进入短训练的预设门槛

先在每个模型种子内平均4块，再跨三个种子等权汇总。**每个版本单独判定，不要求v2先胜v1。** 某任务通过需要同时满足：

1. TRUE平均A梯度余弦>0；对PERM均值和RAND均值的平均余弦优势均≥0.05，各至少2/3种子同向。
2. TRUE/PERM/RAND可作非零配对比较的覆盖率≥80%；未收敛/数值异常满足M0规则。
3. 平均 `RTRUE≥1e-4`（基准CE的0.01%）；至少2/3种子为超过数值误差的正改善。
4. TRUE相对MEAN-Y、PERM均值、RAND均值、FIT+QRY-CE，在B上的平均额外CE改善均>0，且各至少2/3种子同向。若null为零，仍保留其真实单步结果，不能删除该对照。

| 通过情况 | 决策 |
|---|---|
| 同一版本两个任务均通过 | 进入该版本M2，两个任务都做 |
| 仅一个任务通过或结果不可判定 | 不宣布稳定有效；可另登记补到5种子或一次有针对性的数值检查，本轮不自动扩训练 |
| 两个任务均不通过 | 暂停该版本M2，按Oracle/MEAN-Y/QUERY-CE结果定位原因 |

“0.05、1e-4、2/3、80%”是投入下一阶段的筛查约定，不是统计显著性水平。Oracle不能改善B时，不能直接把失败归因于TQG；A只有16张，可能存在批次噪声或泛化差。
