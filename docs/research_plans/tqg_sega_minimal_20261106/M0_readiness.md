## 执行顺序

1. 完成执行清单中的最小适配并通过合成测试，封存代码/配置/数据/索引SHA。
2. 先训练seed3405的source fit模型，100epoch，以source validation CE选起点。所有方法/目标共用该源缓存。
3. 在0→1、θ0上执行M1清单的前3个块，对v1/v2测量查询耗时、峰值内存和数值。临时更新后恢复原参数与buffer；这些块可复用于M1，不额外算独立样本。
4. 工程检查通过，再补seed3406/3407。源模型总数上限3；不为每个目标/版本重训。

## 检查表

| 检查 | 记录/判断 |
|---|---|
| 数据与源角色 | cache与源清单SHA一致；779/196/109，fit/query互斥；目标输入无y |
| 源学习 | 每epoch fit CE、源val CE/BA、选中epoch、类别召回；与fit标签比例常数分类器比较 |
| 源模型可用性 | 至少2/3种子的source val NLL低于该常数基线且BA>50%；不足则先标记源初始化信号不足，不删除失败种子 |
| 确定性状态 | 查询前后参数/buffer哈希相同；同RNG同输入可回放；正常适配BN统计不变 |
| v1 | 有效方向数、odd/even列RMS、系数范数、源拟合误差、目标纠错范数；是否出现全部无效或差分退化 |
| v2 | rank及SVD阈值、核尺度与源目标交互、W范数、gap、termination、converged；是否退化为零反馈 |
| 梯度执行 | v1损失梯度与 `-mean(JTᵀ rhat)` 对照；v2与 `-Vd` 对照；普通SGD实际增量与规定增量对照 |
| 反馈大小 | β‖g反馈‖/‖gfit‖，分母为零时NA；同时记录实际参数变化和目标logit变化 |
| 资源 | 预训练总时间；查询/求解/反传各段时间与内存；CPU/GPU分开记录 |

FP32梯度等式用相对误差 `‖g-g_ref‖/max(‖g_ref‖,1e-12)≤1e-4`，接近零的情况另报绝对误差。SGD更新还需考虑写回FP32参数的舍入：逐坐标核验 `θnew≈round32(θold-ηg)`，记录实际增量/理想增量范数比，不能用近零分母制造巨大相对错误或把无变化当作成功反馈。

## 数值与预算规则

- 非有限、状态被探针修改或梯度等式异常：停下来修复工程问题，未修复前不判研究成败。
- v2达到迭代上限但有限：保留原结果并标为近似。数值fallback占该版本/任务全部12块超过10%，或v2未收敛占实际非零秩校准次数超过10%，先判数值证据不足，不扩大连续训练。没有任何非零秩校准时记不可判定，零秩另外进入M1覆盖率统计。
- 有效反馈稀少、源目标核交互接近零：这可能是模型/支持问题，不伪装成“代码没跑”；交给M1报告覆盖率。
- 用实测中位数/p95估算后续预算，不预先编造小时数。M1最多48次主几何/反馈构造；两版进入M2时，每版600次反馈构造，另有基线训练与评价。
- 不因耗时擅自减少query196、截断v2非零方向或换更小骨干；如确实超预算，单独登记近似实验。此轮不做超参数搜索。

源模型可用性不通过时，本方案暂停M2。可以完成小范围M1用于解释，但不能将其负结果直接解释为TQG迁移机制失效。
