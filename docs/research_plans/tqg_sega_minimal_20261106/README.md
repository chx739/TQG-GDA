## 先理解这一轮要回答什么

换了 SEGA 骨干后，先重新训练三个源模型，检查反馈是不是有用的建议；只有建议有证据优于对照，才连续走 50 步。最终要区分：

1. **能算对、能运行**：代码、BN、数值和执行是否正常？
2. **源标签真的有帮助**：是否优于乱标签、没有逐图标签关系的反馈和随机扰动？
3. **TQG 的读取有帮助**：是否优于直接用相同 query 标签做普通源 CE？
4. **连续执行有帮助**：同起点、同预算下，目标开发集是否稳定改善？

前面一项通过，不能代替后面一项。最小筛查不是 ICML 完整实验，也不能用三种子结果宣称统计显著。

## 为什么选择这个范围

- **只用 Mutagenicity**：源 query 有 196 张，先减少 PROTEINS 小样本/不平衡带来的混杂。
- **先做 0→1、0→3**：固定选择图规模索引的相邻端与较远端，覆盖不同迁移情况。它们是否在新骨干上更容易/更困难仍需实测。0→2 留到扩展，不根据本轮成绩换任务。
- **三个模型种子 3405/3406/3407**：可观察跨起点一致性；一个种子只能证明能跑。
- **保留 100 epoch 源预训练，后续先限 50 步**：源模型只训练三份、跨任务和版本共用。把主要省算力放在适配和诊断矩阵上。
- **不直接与旧表格相减**：新旧骨干、读出、精度、源预训练 batch 等不同；这一轮只在新实现内部公平比较。

## 核心对照一眼看懂

| 方法 | 做什么 | M1 | M2 |
|---|---|---|---|
| FROZEN | 新源模型不动 | 是 | 是，直接复用起点 |
| FIT-CE | 只继续 fit 的源 CE | 是 | 是 |
| FIT+QRY-CE | fit CE + 0.1 × 同一批 query 的 CE | 是 | 是 |
| v1 / v2 TRUE | 各自文档的真实源标签反馈 | 是 | 通过筛查的版本 |
| PERM | 打乱 query 的标签—图对应关系，保留标签比例 | 每版 3 个固定置乱 | 每版固定第 1 个置乱 |
| MEAN-Y | 每张 query 使用相同的源 query 平均标签向量，再减各自预测 | 是 | 本轮不增加训练轨迹 |
| RAND | 同可执行空间、与 TRUE 等范数的随机梯度 | 每版 3 个随机方向 | 本轮不增加训练轨迹 |
| ORACLE-A | 开发集 A 标签给出的真实梯度，仅用于临时诊断 | 是 | 禁止连续 Oracle 训练 |

FIT+QRY-CE **不等于旧实验“全源标签预训练”**：它从同一个 fit-only 起点继续，直接使用与 TQG 相同的 query 标签，是一个便宜的读取方式对照。MEAN-Y **不等于平均残差**：它仍保留各图不同的当前预测，用来检查收益是否必须依赖逐图标签关系。

## 结论如何分流

| 观察 | 可以说什么 | 下一步 |
|---|---|---|
| 数值失败、反馈长期为零或校准普遍不收敛 | 当前执行或数值配置尚不能支撑判断 | 先修复，保留失败记录 |
| Oracle 能改善，TRUE 不能 | 问题更靠近监督读取/迁移，而非“没有可改善方向” | 查 v1 响应或 v2 核/读出 |
| TRUE 与 MEAN-Y / PERM 相当 | 尚无逐图源标签迁移证据 | 分析标签项与预测项，不加训练轮数补结论 |
| TRUE 胜 FIT-CE，却不胜 FIT+QRY-CE | 可能只是多用源标签有帮助 | 暂无 TQG 读取增量证据 |
| M1 有信号，M2 没收益 | 初始反馈未能持续有效，或当前执行强度不合适 | 查反馈随步数漂移、源目标冲突和幅度 |
| M1/M2 均稳定胜过对照 | 值得扩大验证 | 另登记 0→2、种子3408/3409和200步 |

任何失败仅针对这套设置；任何通过也只是下一轮投入的依据，不是已经证明全部跨域假设。
