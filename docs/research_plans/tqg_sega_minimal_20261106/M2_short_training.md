# M2：通过筛查后，最多50步的配对训练

白话：好建议需要反复执行仍有帮助。每个方法从同一源模型出发，看到同样的批次，只改变它怎样使用query标签。

## 1. 最小矩阵与预算

| 臂 | 新轨迹数量，两版都进入时 | 规则 |
|---|---:|---|
| FROZEN | 0 | 复用三个源模型，分别预测两个域 |
| FIT-CE | 3 | 每种子一条；目标不参与训练，同一模型评价两个域 |
| FIT+QRY-CE | 3 | 同起点、同fit16/query196；CEfit+0.1CEquery |
| v1 TRUE | 6 | 2任务×3种子，文档odd+even主版本 |
| v1 PERM | 6 | 同算法、同批次、同随机方向调度，仅源query标签改为固定perm/1 |
| v2 TRUE | 6 | 2任务×3种子，完整数值有效空间及joint主版本 |
| v2 PERM | 6 | 同设置，仅源query标签改为固定perm/1 |
| 合计 | **30** | 每条50步，最多1,500次连续更新；TQG反馈构造共1,200次 |

仅一版入选时为18条轨迹、900次更新；都未入选时不执行M2。源预训练最多三次、2,100次更新，独立列账。FIT-CE和FIT+QRY-CE共享跨目标结果，不能算成两份独立训练证据。

PERM轨迹的模型会逐渐与TRUE不同，所以后续查询几何也会不同；不强制跨轨迹共用过时的V/W。配对指相同起点、输入ID和随机数调度，**不是不同模型状态下还使用相同反馈**。

## 2. 执行与评价

- 连续适配输入为完整无标签目标池，batch16；query每步全196，fit每步16；lr/β/优化器按共同协议固定。
- 每一步重新构造当前模型的查询；保留参数/BN状态检查和当前生产日志。两个方法不要求相同计算量，额外耗时和内存需要单列。
- 保存step0、10、50的模型和全目标预测，主结果为step50。当前生产入口只保存最终模型，因此中间快照由实验driver补齐，不能假装现成支持。
- 所有待比较轨迹和预测封存后，才由开发评价器读542张开发标签；完整final标签禁止读取。
- 查询臂记录rank/有效方向、系数或W范数、反馈/源梯度范数比、源残差、核交互、收敛率和fallback率。用固定0/10/50观察点诊断漂移，不能按目标结果早停或挑checkpoint。
- 本轮不加入Adam、目标batch扫描、GINE、PROTEINS、全源重新预训练或伪标签训练。它们属于后续扩展，不让最小矩阵变成一次大搜索。

## 4. 值得扩大验证的标准

每版分别判断，两个任务都需要：

1. step50相对FROZEN、FIT-CE、FIT+QRY-CE和本版PERM，平均NLL均降低，且每个比较至少2/3种子同向。
2. 相对FIT-CE平均BA至少提高0.5个百分点；相对其余三个对照平均BA不降低；披露实际差值和全部种子，不仅给是否通过。
3. 数值异常/未收敛比例满足M0约定，改善不是来自删掉失败种子或选中step10。

满足后只称“新实现出现值得扩大验证的信号”。未达到0.5个百分点但NLL有一致改善，登记为弱信号/预算不足，不能说已证明无效，也不能直接改用最佳epoch过关。50步负结果只限制当前短预算设置。

若TRUE和PERM都优于FIT-CE但没有差别，仍缺真实标签迁移证据；若TRUE不胜FIT+QRY-CE，仍缺TQG读取的额外收益。后续方案需单独登记五种子、三个方向、200步及简单伪标签/更全面源监督基线，再谈完整算法比较。
