# 如何验证 TQG 能不能 work

状态更新（2026-10-24）：**首轮启动包、E2、E3 与 E4 补充实验已完成，整套验证路线尚未全部完成。**

- 已完成：39 项正确性测试；首轮五种设置各 5 个模型种子、固定模型 E1 的 Target/Random/Source 比较；E2 新增 45 个完整适配、5 个精确预算 warmup、45 次旧 checkpoint 重评，以及源/目标残差迁移诊断（5 模型 × 20 block）。
- E2 已补：Source 方向完整训练、Linear/Odd 的同 K 与同响应列数消融、3 个 query 标签打乱种子、全部源标签的 700 次 warmup 更新对照。结果/作业指纹、数据角色和批次序列已审计。
- E3 已补：query=8/16/32、ridge=0.01/0.1/1/10 的源内部配对诊断，Target/Random 两种方向，5 个模型各 20 个 block；39 项核心测试与 6 项新增协议测试通过。源选择封存后完成 20 个新适配、85 条分类评估（含 45 条旧模型重评），原始诊断为源 4800 条、目标 1200 条。
- E3 结果：当前初始源模型上，12 个 Target 组合均未优于零纠错；增加 query 能减轻源内拟合误差，增强 ridge 主要压小纠错，未通过预定源域判断条件。扩大 query 的分类均值仅比原 TQG 高 0.14 个百分点，尚无稳定优势。
- E4 已补：平均残差、响应回归加常数项，query=16/32，各 5 个种子；20 个新适配、105 条分类评估（65 条为旧 checkpoint 重评）、源/目标诊断各 2400 条。核心测试已扩展为 47 项，原 TQG 10 步重放仍逐位一致。
- E4 结果：平均残差在独立源图上的误差低于原 TQG，但仍未优于零纠错；加入常数项反而更差，未支持“只是漏掉平均偏差”的解释。完整训练未显示新对照的稳定优势；这仍只是单任务探索，不能直接否定整个方向。
- 部分完成：query/ridge 的小范围敏感性。未完成：其他超参数、同时间预算、其他域方向/数据集、外部方法比较和最终保留集评估。
- 使用官方重新处理的数据新协议，保留原源 ID 划分；当前任务的默认 TQG 仍未显示合理基线之上的优势。残差拟合在换一批源 query 图时已经恶化，需先检查源内泛化。
- 详见 [首轮报告](/home/hxchen/TQG_runs/20261023_proteins_official_pilot/run_report.md)、[E2 报告](/home/hxchen/TQG_runs/20261023_proteins_followup_v2/run_report.md)、[E3 报告](/home/hxchen/TQG_runs/20261024_source_generalization_e3/run_report.md) 与 [E4 报告](/home/hxchen/TQG_runs/20261024_residual_baselines_e4/run_report.md)。最终 139 张目标保留图的标签未参与评估。

以下是完整验证路线；其中的后续实验不能当作已经运行的结果。现有正确性检查也不能替代方法有效性证据。
之前的 [E1](E1_首个验证实验.md) 是机制诊断，不能代替完整训练实验；本文件补充整体证据链，不修改 E1 已写下的参数和判断标准。

## 1. 先区分三种结论

1. **代码能运行**：数值、梯度、数据角色和恢复流程正确。
2. **方法有实际帮助**：完整适配后，目标图分类稳定优于源训练基线。
3. **提出的机制成立**：增益确实与目标选方向、源监督迁移或有限非线性响应有关。

可能出现“方法有帮助，但目标选方向不重要”；也可能出现“单步方向不错，但长时间训练没有收益”。
这些都需要按实际结果收缩结论，不能相互替代。

## 2. 第一优先级：完整训练是否改善分类

第一项真实任务用现有 PROTEINS `idx` 域 0→1，之后扩展。

| 组 | 训练方式 | 回答什么 |
| --- | --- | --- |
| A：源预训练后直接测试 | 只在 source fit 上 warmup，不继续训练 | 适配前的起点 |
| B：继续源训练 | 与 TQG 共用 fit-only warmup，继续 source fit CE | 排除“只是多训练了一段时间” |
| C：全部源训练标签基线 | fit+query 都用于源 CE，重新做对应 warmup 和后续训练 | TQG 是否优于直接利用同一批可用源标签 |
| D：完整 TQG | source fit CE + TQG 目标反馈 | 最终是否有实际收益 |

不能只和 A 比：TQG 有额外训练步骤，也利用了 query 的标签。
不能只和 B 比：B 没有像 TQG 那样使用 query 标签。C 是实际价值的重要参照。
若 D 仅优于 B、未优于 C，只能说在保留 query 的受限源训练设置下有收益，尚未证明它优于直接使用全部源标签。

训练配置：

- B：`configs/source_only_same_fit.json`
- C：`configs/source_only_all_labels.json`
- D：`configs/tqg_development.json`
- A：直接评估 D 使用的 fit-only source `best.pt`

对 B、D 以及后续 Random/Source/响应消融，同一 seed 必须复用同一份 fit-only warmup checkpoint。
C 因源监督池不同，使用自己对应的源训练 checkpoint；数据角色和成本单独记录。

**指标：**目标 accuracy 为最直观结果，同时报告 balanced accuracy、CE、各类召回率。
五个配对模型种子报告均值、标准差、逐 seed 差值和低于基线的次数。
后续跨域汇总时，同时报告各任务结果、任务平均差值和负迁移率，不能只报告最好的任务。

主结果按当前预定规则，用 source validation CE 选 checkpoint；额外报告固定末步作为诊断。
若 source validation 最后选回 step=0，要明确报告。不能从目标曲线上挑最好的 epoch 当主结果。

以上是首轮预定规则，保留不改。E2 是已知首轮开发结果后的探索性补充，运行前单独固定“第 200 步”为主指标、source-selected 为次指标；两套结果同时报告，不把它写成未见过目标开发结果的确认性结论。

**初步支持：**在预先指定的任务上，D 对 B 有可重复增益，且对 C 也有实际收益；随后需跨任务复验。
不预先承诺“提高 1% 就有效”：是否有价值需结合任务难度、种子波动、样本量和计算代价判断。

## 3. 第二优先级：目标选方向是否必要

| 组 | 唯一改变的部分 |
| --- | --- |
| Target | 目标输出投影产生方向 |
| Random | 随机参数方向 |
| Source | 源 query 输出投影产生方向 |

使用相同源模型、批次抽样规则、K、rho、响应模式、岭回归、目标 JVP 规范化和训练步数。
先用固定模型的 E1 测单步方向是否有用，再将三种方法完整训练，比较最终分类。

- E1 好、完整训练也好：有一致证据支持目标查询。
- E1 好、完整训练不好：检查反馈强度、源 CE 冲突、优化过程和选模规则。
- Target≈Random：目标选方向的独有贡献不足，即便整个训练框架仍可能有用。
- Target≈Source，二者优于 Random：证据偏向“数据驱动方向有用”，还不能声称目标特异优势。

固定 K 匹配候选方向数，不保证有效方向数、响应列数或运行时间完全相同；这些量一起报告。
后续再补同时间预算比较，不能把同 K 结果写成同算力结果。

现有配置：`random_probes.json`、`source_probes.json`；固定模型诊断见 E1。

## 4. 源残差到目标纠错的关系是否真的迁移

这是最核心的不确定性之一：源上组合得好，不代表目标上方向正确。

在保留的目标诊断集上检查：

- 记录源残差拟合误差，和目标纠错的实际效果同时看，不能仅用源误差下降证明迁移。
- 将预测目标纠错与 `onehot(y_target) - p_target` 比较方向是否一致；零纠错单独计数，不能删掉。
- 用 E1 检查反馈训练梯度是否与另一批目标图的真实分类梯度一致，以及同长度试走后的 CE。
- 加一个负对照：**只打乱求组合权重时使用的 source query 标签**，保持 source fit 的正常训练和其余流程不变。重复多个预定的打乱种子，报告有效打乱程度。

如果源拟合很好而目标反馈持续朝错的方向走，说明跨域关系假设可能失效。
如果打乱 query 标签几乎不影响结果，增益未必来自预期的监督迁移，也可能主要来自训练中的其他正则化效果。
负对照变差本身也不足以证明全部机制，需要结合正常标签的正向反馈和端到端收益。

E2 已实现并运行目标残差分析与 query 标签打乱对照，同时加入互不重叠的源 query 批次检验源内泛化。诊断直接修正 logits，与 E1 的参数梯度/参数更新诊断分别解释。

## 5. 有限非线性响应是否有额外价值

| 组 | 使用的响应 |
| --- | --- |
| Linear | 精确局部一阶 JVP |
| Odd | 有限正负扰动的奇响应 |
| Odd+Even | 奇响应 + 偶响应 |

现有配置：`linear_jvp.json`、`odd_only.json`、`tqg_development.json`。
这能区分局部线性信息、有限扰动效应、加入偶响应三者的作用。

**两类公平比较要分开：**

1. 固定候选方向数 K，比较完整设计的收益和实际开销。
2. 尽量匹配响应列数或计算预算，检查 Odd+Even 是否仅因特征更多/计算更多占优。

同 K 时，Odd+Even 通常每个有效方向有两列响应，而另外两组每个方向一列；不能忽略这个混杂因素。
若三组相近，应弱化“有限非线性响应提供额外可迁移信息”的贡献表述。E2 已运行 K=4 三组与 Odd/Linear K=8 的列数匹配版本；计算时间仍未匹配。

## 6. 稳定性、适用范围与成本

在第一项任务有信号之后再扩展，避免一开始同时铺开所有网格。

- **跨任务：**至少增加一个独立数据集，如已有索引的 NCI1，并预先指定多个域方向。不能把同一数据集的所有方向当成多个独立数据集。
- **跨随机性：**每项主要比较用 5 个配对模型种子；先报告各任务，再汇总任务平均。
- **超参数：**重点检查 rho、K、feedback_weight、ridge。先选少量预定值逐项变动，不做大规模全组合搜索。
- **训练过程：**观察源 CE、反馈范数、系数范数、无效方向率、选模 step、数值异常，判断收益是否只在极窄条件下出现。
- **同分布检查：**如另设源分布的伪目标池，必须预先独立留出，不能复用 source validation 同时训练和选模；检查适配是否经常损坏本来不错的模型。
- **成本：**分别报告 warmup 时间、适配时间、峰值显存、有效方向数和失败率。与基线比较相同步数与相同时间预算；两种结论不要混用。

全源标签基线的 warmup 池更大，同 epochs 不代表同样本处理量；必须记录源监督更新次数和实际耗时。
探索性超参数/方法修改只用源验证、源内部伪目标或明确保留的目标开发标签，不能反复查询最终目标测试标签。

## 7. 从“work”到“有研究竞争力”还差什么

内部对照有结果以后，再加入同一骨干上的简单伪标签、域对齐基线，以及兼容当前设置的图分类 UDA 方法。
可先参考经典 [DANN](https://jmlr.org/papers/v17/15-239.html) 和图级方法 [CoCo（ICML 2023）](https://proceedings.mlr.press/v202/yin23a.html) 的思想与实验设置。
它们不是 2026 年最新方法清单；正式论文还需要单独核查近期相关方法及公开实现。

与外部方法比较时，核对图级/节点级任务、源数据是否可访问、输入属性、标签预算、域划分和选模规则。
优先在统一协议下重跑，不直接拿别人论文的数字与不同划分的 TQG 相比。
没有稳定胜过简单内部基线之前，不必先投入大量时间做外部方法复现。

## 8. 建议的最小启动包

**完整训练部分：**A/B/C/D 四组，其中 A 是已有 warmup 的直接评估，不额外训练。
加 Random 一组，五个模型种子，用来同时看实用收益和目标选方向的价值。

**小诊断部分：**按 E1 做固定源模型的配对分析，它可复用这些 fit-only warmup。

如果端到端和机制结果都有信号，再扩展 Source 方向、Linear/Odd、打乱 query 标签、第二数据集与跨域任务。
若首先发现实现或数值问题，先修正再跑；若只是一个任务未获益，记录失败设置并按预定计划复验独立任务，不把全方法直接判死。

## 9. 数据与评估边界

沿用 E1 的 label-blind 目标 diagnostic/final 划分，并保存两个目标索引。
第一轮端到端比较可在 diagnostic 子集上评估，允许它服务于研究决策；最终标签继续留出。
适配可以按声明的 transductive 协议访问全部目标输入，但不能访问其标签。
方法和分析计划固定后，才在最终保留集上做确认性评估；不要直接对整个目标池反复调参后称其为未触碰测试。

设计时尚缺原始图缓存；现已直连下载官方 PROTEINS 并完成重新处理，核验现有索引的边数分组边界，创建并记录独立的新缓存协议，没有覆盖原 manifest。
本轮 PyTorch CUDA 不可用，实际实验全部在 CPU 上完成。
未来更换数据版本时，仍需核验图 ID/域索引对应关系并明确记录协议差异。
