# E1：目标图选出的方向，真的比随机方向更会纠错吗？

**这是第一轮机制验证方案，不是已有结果，也不是完整的 ICML 实验。**
先回答 TQG 最核心的一件事：在同一个模型上，用目标图选方向，是否能比随机方向产生更有用的纠错？
原方法见 [`TQG_Graph_Level_GDA_Design.md`](TQG_Graph_Level_GDA_Design.md)；本文的诊断划分、指标和阈值是新增实验设计。

## 1. 先用一句话理解

**让两种方法给同一个学生提修改建议，再拿另一张试卷的标准答案，检查谁的建议更有帮助。**

- 学生：只在源 fit 图上预训练好的 GNN。
- 建议 A：目标图选方向 → 源标签学组合权重 → 产生目标纠错。
- 建议 B：随机选方向 → 后续完全相同 → 产生目标纠错。
- 考官：另一批目标图的真实标签，仅用于实验诊断。

每次都从同一个学生、同一份参数开始。检查建议后，不真的把修改保存下来。
因此这轮实验没有反复训练带来的路径差异。

## 2. 研究问题和可以被推翻的猜想

**问题：**目标数据参与“选方向”，是否提供了随机方向没有提供的信息？

**猜想：**在预先固定的任务和参数下，目标方向生成的反馈，其梯度比随机方向更接近另一批目标图的正确分类梯度；沿这个反馈试走同样长的一步，也更能降低目标分类损失。

这里没有假设“对目标输出影响大的参数就一定正确”。恰恰是在检验这个缺口。

这轮结果能支持“这个任务、这个源初始化附近，目标查询可能有用”。
它不能单独证明最终准确率提高、所有域都有效、非线性响应不可替代，或足以投稿 ICML。

## 3. 用现有哪个任务

首个任务使用已有 SEGA 包的 **PROTEINS，`idx` 域 0 → 域 1**，直接复用现有索引。
选择它是因为代码和源划分已经对接，并非宣称它代表所有 GDA 场景。

- 源划分：`data/splits/PROTEINS_idx_0_source.json`，保留原来的 250 train / 28 validation。
- train 再按固定种子 431、fit_fraction=0.8 分成 fit/query；具体人数以逐类划分后的角色文件为准。
- 目标池：`idx/idx_PROTEINS_1.npy`。
- 原始缓存：需要与源清单 SHA256 一致的 TU/PyG `processed/data.pt`；当前包未提供。
- 如果只能重新处理数据，用 `prepare_source_split.py` 创建并记录新协议，不能直接替换原哈希假装复现。

图级 UDA 的问题背景可参考 [CoCo（ICML 2023）](https://proceedings.mlr.press/v202/yin23a.html)；数据集信息见 [TUDataset 官方列表](https://chrsmrrs.github.io/datasets/docs/datasets/)。
这里的具体域索引以本地 SEGA 资产为准。

## 4. 数据怎么分，避免拿考试答案改方法

| 数据角色 | 用途 | 可否提供标签 |
| --- | --- | --- |
| Source fit | 源预训练；这轮结束后保持模型固定 | 可以 |
| Source query | 用响应拟合源残差、求组合权重 | 可以；不能混入预训练 |
| Source validation | 按 CE 选择源预训练 checkpoint | 可以 |
| Target diagnostic，约一半目标 ID | 本轮机制诊断，可以影响后续研究决策 | 仅独立诊断时读标签 |
| Target final，剩余目标 ID | 方法固定后的最终评估 | E1 不读标签 |

目标 diagnostic/final 用 **ID 随机划分**，种子 271828，划分前不看目标标签；所有模型种子共用同一划分。
读诊断标签前，脚本先将角色、参数、checkpoint 和代码哈希写进 `protocol.json`。

**诊断集的标签已经服务于研究，不能再冒充从未见过的最终测试集。**
这只是开发阶段的 oracle 分析；主训练仍然不读目标标签。
后续可以在声明清楚的 transductive 协议中使用无标签目标输入，但最终测试标签需继续保留。
以后正式评估时必须使用记录下来的 `final_target_ids`，不能直接对整个目标池报告“未触碰测试”成绩。

每个 block 从 diagnostic 池取两批**互不重叠**的图：

- `T_query`：16 张，提供无标签输出，用来选方向、算响应和反馈。
- `T_eval`：32 张，没有参与这次查询；仅考官用它的标签评价反馈是否能推广到别的图。
- 同时从源 query 取 16 张，所有方法共用这批图和标签。

不同 block 可以重复抽到同一张图；因此 block 不是独立实验种子。

## 5. 对照组：每次只换方向的来源

| 组 | 方向怎么来 | 后续响应、源残差拟合、目标反馈 |
| --- | --- | --- |
| Target（主方法） | 目标图输出的随机投影反传到 encoder | 相同 |
| Random（主对照） | encoder 参数空间的随机方向 | 相同 |
| Source（辅助对照） | 源 query 图输出的随机投影反传到 encoder | 相同 |
| No feedback（零点参照） | 不给修改建议 | 参数不动，损失变化为 0 |

前三组均使用目标 JVP 尺度规范化，K=4、rho=0.05、ridge=0.01、odd+even 响应，FP64。
模型、源 checkpoint、数据批次、响应模式、岭回归和试走距离保持一致。
分类头不参与探测，但和 encoder 一起参与反馈更新；与现有 TQG 训练规则一致。

**固定 K 仅匹配候选方向数，不等于固定计算量。**目标方向多了 VJP，随机方向也仍需要目标 JVP。
记录实际有效方向、响应列数、丢弃原因和耗时；不能挑选“恰好成功的方向”重跑。
方法执行次序按 block 轮换，降低首次运行计时的偏差。

## 6. 一次 block 实际做什么

1. 取固定源预训练参数 θ₀，不做适配。
2. 抽同一组源 query、`T_query`、`T_eval`。
3. Target/Random/Source 分别生成目标纠错，全程不用目标标签。
4. 三种反馈全部生成后，才读取 `T_eval` 的诊断标签，计算正确分类梯度。
5. 评价反馈方向；在临时参数副本上试走一步，看 `T_eval` 分类损失是否降低。
6. 只保存指标，不保存试走后的模型。下个 block 仍从 θ₀ 开始。

## 7. 评价什么，为什么

### 主指标：反馈和正确方向有多一致

定义反馈损失与考官损失：

\[
L_{fb}=\frac{1}{2|T_{query}|}\sum_{i\in T_{query}}
\|z_\theta(G_i)-\operatorname{sg}(z_{\theta_0}(G_i)+\hat r_i)\|_2^2,
\quad
L_{eval}=\frac1{|T_{eval}|}\sum_{j\in T_{eval}}CE(z_\theta(G_j),y_j).
\]

均在 θ₀ 处计算完整模型的梯度：

\[
g_{fb}=\nabla_\theta L_{fb},\qquad
g_{true}=\nabla_\theta L_{eval},\qquad
A=\frac{g_{fb}^{\top}g_{true}}{\|g_{fb}\|_2\|g_{true}\|_2}.
\]

训练是沿负梯度走，所以两个梯度同向就表示两个更新同向：

- A>0：小步沿反馈更新，预计能降低另一批目标图的分类损失。
- A≈0：看不出帮助。
- A<0：反馈可能在把模型往错误方向推。

主要比较 **A_target − A_random**。同时要看 A_target 本身是否为正；“比随机少坏一些”不足以说明能纠错。
当梯度不存在有效尺度时单独处理，见第 9 节。

### 次指标：同样走一步后，损失真的降了吗

对非零反馈统一使用：

\[
\theta'=\theta_0-\eta\frac{g_{fb}}{\|g_{fb}\|_2},\qquad
\eta=\alpha\max(\|\theta_0\|_2,1),\qquad
\Delta CE=L_{eval}(\theta_0)-L_{eval}(\theta').
\]

固定两种 α：`1e-4`、`1e-3`，两种都报告，不根据目标成绩挑一种。
同一模型下，各组每次试走的参数距离相同，避免把“方向好”与“步子大”混为一谈。
ΔCE>0 才是损失降低。另报“损失下降的 block 比例”、反馈梯度范数和零反馈比例。

这是反馈方向的诊断步，不是完整 TQG 的 Adam + 源 CE 更新。真实适配效果仍需后续实验。
不把单步 accuracy 设为主指标：概率变好但尚未跨过分类边界时，accuracy 可能完全不变。

**举例，以下纯为示意：**同样一步后，Target 的 CE 从 0.70 降到 0.68，Random 从 0.70 升到 0.71，才说明这一轮 Target 建议更有用；这些数不是实测结果。

## 8. 预算与重复

- 源模型种子：3405、3406、3407、3408、3409；每个只在 fit 上预训练 100 epochs，按 source validation CE 取 best。
- fit/query 划分、目标 diagnostic/final 划分保持不变。
- 每个源模型做 20 个配对 block；每个 block 比较 3 种查询方向和零反馈参照。
- 先对同一模型的 20 个 block 求均值，再报告 5 个模型种子的均值、样本标准差、各种子差值。
- 不把 100 个 block 当成 100 个独立模型，也不声称覆盖了数据集重划分的不确定性。

目前没有真实图缓存和实测耗时，因此不编造 GPU 小时或保证当天跑完。
开始正式运行前可用独立的 2-block 成本配置估算时间；只用于查运行错误和测成本，不能混入正式结果，也不能据目标分数更改方案后称其“预注册”。

估算公式：

`总成本 ≈ 1.3 × [5 × 单个源预训练时间 + 5 × 20 × 单个完整配对 block 时间]`。

若预算不足，先记录修改后的新协议再运行；1 个种子只能算探路结果。

## 9. 提前约定怎么判断，避免跑完才改标准

下面阈值是**早期研究的工程判断标准**，没有历史数据支持，不等同于统计显著性或投稿门槛。

**继续投入：**五种子全部完成，且同时满足：

1. Target − Random 的种子平均 A 差值 ≥0.05，至少 4/5 种子差值为正。
2. Target 的总体平均 A>0。
3. 在两种固定试走距离上，Target 总体平均 ΔCE>0、优于 Random，且每种距离至少 4/5 种子优于 Random。
4. 没有数值错误、模型被意外修改或越界读标签；每个种子无信息 block 比例不超过 10%。

**当前设置不支持目标方向优势：**平均 A 差值 ≤0，并且至少 3/5 种子不优于 Random。
这不等于推翻所有 TQG 变体，说明这组任务/初始化/参数下核心猜想缺乏支持，应先定位原因。

**其余情况：**效果小或不一致，结论不确定；如需扩大样本，另建协议，保留本次结果。

异常处理：

- 没有有效探测方向或反馈梯度接近 0：A 记 0、ΔCE 记 0，保留在平均中。
- 考官梯度接近 0：整个 block 的各组 A 都记 null，统一从 A 的平均中排除，并报告数量；ΔCE 仍报告。
- 非有限数值直接报错，不能默默跳过差的 block。
- 诊断池或源 query 不够大时直接报错，不静默缩小 batch。

## 10. 配置和运行

实验计划：`configs/diagnostics/e1_target_vs_random.json`，它是诊断专用配置，不是训练器的 `--config`。
预训练仍用 `configs/tqg_development.json`。

单个种子的示例（替换真实缓存路径；输出目录必须不存在）：

```bash
cd /home/hxchen/TQG_GDA

# 当前机器可用的解释器；其他机器可换成自己的 Python。
TQG_PY=/home/hxchen/anaconda3/envs/bfn4jet/bin/python

"$TQG_PY" scripts/run_experiment.py source \
  --data-path /path/to/PROTEINS/processed/data.pt \
  --config configs/tqg_development.json --seed 3405 \
  --output /tmp/tqg-e1-source-3405

"$TQG_PY" scripts/run_diagnostic.py \
  --checkpoint /tmp/tqg-e1-source-3405/source/best.pt \
  --data-path /path/to/PROTEINS/processed/data.pt \
  --plan configs/diagnostics/e1_target_vs_random.json \
  --output /tmp/tqg-e1-diag-3405
```

其他四个种子重复同样步骤，只改变模型 seed 和输出路径，不改变计划文件。
若使用新源协议，两个命令都额外指定同一个 `--source-split /path/to/new_protocol.json`。

诊断输出：

```text
protocol.json   # 读诊断标签前固定的数据角色、配置与哈希
target_diagnostic.npy / target_final.npy  # 已分开的目标索引，便于以后独立评估
blocks.jsonl    # 每个 block 的图 ID、各组方向指标、试走损失、反馈哈希和查询耗时
summary.json    # 一个源模型种子的 block 均值、Target−Random 差值
```

五个种子完成后：

```bash
"$TQG_PY" scripts/summarize_diagnostic.py \
  --plan configs/diagnostics/e1_target_vs_random.json \
  --summaries /tmp/tqg-e1-diag-3405/summary.json \
              /tmp/tqg-e1-diag-3406/summary.json \
              /tmp/tqg-e1-diag-3407/summary.json \
              /tmp/tqg-e1-diag-3408/summary.json \
              /tmp/tqg-e1-diag-3409/summary.json \

```

汇总器拒绝混合不同计划、不同数据角色或重复 seed。缺少五种子时只报告未完成，不给支持性结论。

## 11. 看完结果下一步是什么

- Target 优于 Random，也优于 Source：值得研究目标特异信息究竟来自哪里，再做完整适配和跨域复验。
- Target 与 Source 相近、都优于 Random：也许“数据驱动的方向”有用，但目标独有优势尚不清楚。
- 三者都无法产生正向反馈：先查源拟合误差、源目标关系变化、反馈符号/尺度和源模型状态；不要马上增加相似度网络来遮盖问题。
- 查询 batch 变好、独立 eval batch 不变好：可能只纠正了当前一小批图，迁移性不足。

若 E1 有信号，下一轮再验证 **finite odd+even vs odd-only vs linear JVP**，然后进行带 source CE 的完整 TQG 适配，对比同 fit 源训练与全部源标签训练，并扩展独立数据集/域方向。
用户提出的相似度加权与辅助自监督信号适合作为后续有针对性的改进，不在 E1 同时引入。
