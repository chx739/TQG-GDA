# 新 SEGA式 TQG v1/v2 最小验证：真实结果

日期：2026-11-07；执行分支 `TQG`；执行代码提交 [`140a73b`](https://github.com/chx739/TQG-GDA/tree/140a73becb112d181a36b66dadc0b8cce38e55fb)。

**M0 与 M1 已完成；两版均未通过预设研究门槛，M2 按方案不启动。** 源模型正常学习、查询和梯度数值检查通过，但四个“版本×任务”组合的平均独立单步额外收益均为负。不能据此声称算法在所有设置下无效；本轮证据不支持直接扩大连续训练。

## 1. 做了什么，没把什么算作结果

依据[冻结方案](../../research_plans/tqg_sega_minimal_20261106/README.md)，重新训练三个新 SEGA GIN 源模型；没有用旧骨干 checkpoint。然后固定各源模型，每个任务/种子独立抽四块输入，分别构造 v1/v2 的反馈和对照，从同一起点临时更新一步，在另一批目标图上评价。

| 设置 | 本轮实际执行 |
|---|---|
| 数据/任务 | Mutagenicity，0→1、0→3；SEGA 图规模域索引，非官方自然域 |
| 模型种子 | 3405、3406、3407；均保留 |
| 骨干 | GIN，3层，hidden64，embedding16，二分类线性头；35,957参数 |
| 源角色 | 779 fit、196 query、109 validation；query不参与源预训练 |
| 新源训练 | 每种子100epoch、batch128、Adam lr0.001，共700步；源val最低CE选起点 |
| M1每块 | fit16、query全196、目标A16；独立B全271评价；两版图ID相同 |
| 临时步 | SGD，lr0.0003，β0.1；每臂重新从θ0开始，无连续适配 |
| 网络/精度 | eval固定BN运行统计与dropout；参数可导；CPU单线程，主FP32，v2核与校准FP64 |
| v1 | 目标方向4个、ρ0.05、ridge0.01、odd+even |
| v2 | H+A核、完整数值有效空间、joint校准、λW0.01 |
| 完成规模 | 3个新源模型、2任务×3种子×4块×2版本＝48个版本块；624逻辑临时步，共用基线后576实际临时步 |
| M2 | 0条轨迹、0步；未通过门槛，不是运行报错或中断 |

A/B 来自既有目标开发集，图ID不同，但不是从未被历史实验观察过的新测试集。所有不使用目标标签的候选反馈先封存，再读开发标签；final始终不读。结果先在每个种子内平均四块/三个null重复，再对三种子等权统计；±为样本标准差，不把临时步当独立模型。

控制臂：真实源标签 TRUE、三个固定错配标签 PERM、平均标签 MEAN-Y、三个同可执行空间/等范数 RAND、直接源 query CE、以及仅作临时诊断的目标A标签 Oracle。PERM置乱Y，不置乱整个残差；MEAN-Y是 `平均Y-p_i`，仍保留每张图的预测项。PERM/MEAN-Y保留其自然幅度，Oracle/RAND匹配TRUE范数。

## 2. M0：源模型与数值是否正常

源初始化通过标准：至少2/3种子源val NLL低于fit类别比例常数分类器，并且BA>50%。实际 **3/3通过**。这里的BA均为**源验证集**，不是目标域性能。

| 种子 | 选中epoch | 实际训练步数 | 源val NLL | 源val BA（%） | 常数基线NLL |
|---|---|---|---|---|---|
| 3405 | 56 | 700 | 0.240843 | 94.39 | 0.692769 |
| 3406 | 44 | 700 | 0.334102 | 86.10 | 0.692769 |
| 3407 | 99 | 700 | 0.317724 | 85.36 | 0.692769 |

| 工程/数值检查 | 真实结果 |
|---|---|
| v1 有效方向 | 24/24块均保留4个方向；可执行空间数值秩为7或8 |
| v2 数值空间 | 24/24块rank=16，未设置人为秩截断 |
| v2 校准 | 24/24主校准收敛；另一次确定性重放不计独立块 |
| 数值fallback | v1 0/24；v2 0/24 |
| v1 梯度相对误差上限 | 6.70775e-07，低于1e-4门槛 |
| v2 梯度绝对误差上限 | 0；参数辅助损失梯度与−Vd一致 |
| 状态与写回 | 查询与临时步没有改变原模型/buffer；FP32 SGD写回检查通过 |
| 非零配对覆盖 | 四个版本/任务组合均100% |
| 标签访问 | 24次封存、6,888开发图次访问；final访问0 |
| 独立复算 | 48块的v1岭回归/v2读出矩阵关系、文件SHA、逐种子聚合和全部门槛复算一致 |

计算耗时：三份源预训练合计 **101.6秒**；24个配对诊断块合计 **123.1秒**。v1/v2主查询中位数分别为 **0.222 / 2.249秒**；进程累计峰值RSS约 **863.5 MiB**。这些计时不包含实现、合成验收和归档上传时间。

## 3. M1：真实反馈是否有效

方向余弦比较反馈损失梯度与目标A真实CE梯度：大于0表示局部方向一致。另一批B图上的主要增益为：

`R = [CE_B(FIT-CE) - CE_B(FIT+TRUE)] / CE_B(FROZEN)`。

下表将R乘100，单位为**相对基准CE的百分比**；正数代表TQG比继续fit训练更好，负数代表更差。它不是BA百分点。门槛要求平均R至少 **+0.01%**，至少2/3种子超过数值分辨率地改善，同时通过方向、标签/随机/直接query-CE对照等条件。

| 版本 | 任务 | TRUE的A梯度余弦 | R（%，均值±SD） | R改善种子 | 预设验收 |
|---|---|---|---|---|---|
| v1 | 0→1 | -0.1847 ± 0.6298 | **-0.16034 ± 0.24730** | 1/3 | 未通过 |
| v1 | 0→3 | 0.2750 ± 0.2048 | **-0.00647 ± 0.04637** | 2/3 | 未通过 |
| v2 | 0→1 | 0.0030 ± 0.4123 | **-0.23527 ± 0.50243** | 1/3 | 未通过 |
| v2 | 0→3 | -0.0239 ± 0.2373 | **-0.03724 ± 0.12806** | 2/3 | 未通过 |

**有些种子受益，但不够稳定。** 例如v1的0→3有2/3种子改善，另一个种子的负收益幅度更大，等权平均仍为负；v2的0→3也存在同样现象。v1的0→3在A上的平均方向余弦为正，仍未转成B上的稳定改善。

|---|---|---|---|
| v1 0→1 | -0.40389 | -0.16769 | +0.09055 |
| v1 0→3 | +0.02151 | -0.06000 | +0.01907 |
| v2 0→1 | +0.34406 | -0.55182 | -0.49806 |

## 4. 相对对照的增量

仍按 `[(对照臂B CE)−(FIT+TRUE的B CE)] / 冻结B CE ×100` 计算。正值才支持真实标签反馈优于该对照；括号为超过数值误差的改善种子数。PERM/RAND先平均三个固定重复。

| 版本/任务 | 相对MEAN-Y（%） | 相对PERM（%） | 相对RAND（%） | 相对FIT+QRY-CE（%） |
|---|---|---|---|---|
| v1 0→1 | +0.13055（2/3） | +0.04108（2/3） | -0.14585（1/3） | -0.02934（1/3） |
| v1 0→3 | -0.08697（1/3） | -0.09945（0/3） | -0.00719（2/3） | -0.08705（0/3） |
| v2 0→1 | +0.06320（1/3） | +0.60086（2/3） | -0.18535（1/3） | -0.10427（1/3） |
| v2 0→3 | -0.11192（1/3） | -0.19327（0/3） | -0.03759（2/3） | -0.11781（0/3） |

0→1上，真实标签相对部分平均/打乱标签对照有增量，但并未同时带来相对FIT-CE、RAND和直接QUERY-CE的稳定改善。**0→3上，两版TRUE在三个种子中都不如直接QUERY-CE，也都不如PERM均值。** PERM和MEAN-Y幅度未匹配，因此这里不能把差异全部归因于方向，也不能把乱标签更好解读成“标签有害”的普遍规律。

## 5. Oracle 与数值审计告诉我们什么

Oracle-only：用A的真实标签梯度，匹配TRUE范数，仅临时更新 `−ηβgOracle`，然后在B评价。TRUE-only同样移除源fit CE，以区分反馈本身与联合更新冲突。

| 版本/任务 | Oracle-only相对冻结CE改善（%） | TRUE-only相对冻结CE改善（%） | R审计误差均值（%） |
|---|---|---|---|
| v1 0→1 | +0.23592 | -0.17945 | 0.000231 |
| v1 0→3 | +0.01471 | -0.00375 | 0.000169 |
| v2 0→1 | +0.59639 | -0.27632 | 0.000231 |
| v2 0→3 | +0.04370 | -0.03845 | 0.000169 |

四组Oracle-only平均均改善，三个种子各自的四块均值也均为正；TRUE-only的四组平均均为负。这更支持进一步检查反馈的读取与迁移，且联合源CE冲突不是唯一问题。Oracle使用开发标签，只是诊断参照，不能作为无监督方法或连续训练结果。

主表保持FP32结果；另对固定原参数、实际FP32更新后参数和理想更新做FP64损失复算，未重算方向/V/W。误差下限包含FP32机器精度和FP32/FP64同一步损失差分的不一致。主要负结果大于该分辨率，不能简单归为浮点误差。
