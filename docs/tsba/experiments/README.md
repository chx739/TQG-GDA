## 当前能支持的结论

| 问题 | 当前证据 | 尚不能推出 |
|---|---|---|
| score 能否学到有用方向？ | 模拟二维6400步双侧方向准确率99.980%；真实16维900步与经验KDE的法向相对误差仍约69%–90% | 模拟训练预算结论可直接迁移到真实图，或符号一致等于分类收益 |
| 之前失败是否只是训练不足？ | 该二维设置的400步明显不足；原DSM选模仍可能选中较差模型 | 所有性能下降都由训练步数导致 |
| 正确score能否带来足够收益？ | 当前源约束下，简化oracle平衡收益仅约+0.0108个百分点 | 完整非线性分类头的收益上界 |
| 降低边界密度是否改善分类？ | 特定相容模拟分布支持；反例说明不存在无条件保证 | 真实图数据满足低密度分隔条件 |
| TSBA在Mutagenicity上是否有效？ | R1b的正常、反向和同矩阵源对照逐图类别预测一致；增量NLL极小且跨任务不一致；更新主要由源CE驱动 | score已带来增量收益，或完整闭环的效果已被验证 |
| 扩尺度能否验证低密度类别分隔？ | 加倍半径有22条记录通过双侧独立图支持，加倍带宽改善ESS；全部六面板仍无双侧B支持达标点 | 条件通过率为0%，或低密度分隔不存在；正确结论是当前条件比例NA |

方法需要分别满足：表示可读、类别对应有依据、局部密度方向有任务价值、score估计可靠、参数响应能执行有益位移。源CE维持语义，也可能抵消目标请求；应研究收益与源代价的权衡，不能简单认为源约束应该删除。

## 文件组织与存档

`synthetic/`和`real-data/`是分类阅读入口。历史日期目录、报告、执行前JSON协议及归档索引保留原路径，避免破坏已发布链接和证据来源；历史报告中的结论按当时实验理解阅读，最新综合判断以本页及P0为准。

各已执行报告链接到日志、CSV、checkpoint清单和本地不可覆盖压缩档。GitHub保存代码、报告与必要标量证据，大体积模型/输入张量保存在报告注明的本地档案。原始方法设计正文保留为历史设计，不用其“尚未实现”状态判断当前进展。

当前源实验角色按每个`cfg.seed`分层生成，保留约72%/10%/18%比例；诊断留出仅为研究用途，不是TSBA算法要求。R1b完整复用源模型、角色与目标A/B，预登记以NLL为主、BA为辅。下一轮优先研究源项与边界请求的实际权衡；若改以BA为主须另行登记。不直接启动闭环，也不把增加score步数当作已有证据支持的单一修复。
