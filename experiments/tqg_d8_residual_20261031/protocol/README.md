## 3. 如何决定下一步

1. D0失败：修接口、符号、数值或权限，不讨论方法效果。
2. D1真实反馈差，D2 Oracle有效：优先D3/4/8，修估计器；暂停扩大训练。
3. D1同批梯度方向好，但D2的B池效果差：检查目标批次泛化、源目标冲突和步长；执行D6或D8，不把同批夹角当迁移成功。
4. D4相似度有监督价值、但部分区域支持差：进入D5。
5. D3简单KRR足够：优先简化校准，不能继续把最大方向项作为已证实贡献。
6. 真实标签在等范数控制后仍无优势：允许重构或放弃当前读取方式，不以更多epoch掩盖。
7. 候选同时通过D1与D2后，冻结最多两个候选，再进入D9。D8合成成功不能单独替代真实数据门槛。
8. 证据不足、零梯度比例高或Oracle本身不改善B池：结论是“当前诊断不充分”，不是证明TQG无效。

各门槛都是本次事先提出的工程／研究决策阈值，不是历史结果、统计显著性或理论充分条件。运行开始前记录计划SHA；未通过时不得改变阈值把同一次实验改判通过。

## 4. 第一工作包的边界

- 复用5个源fit预训练模型及源SGD的50／200步模型；共45个“任务×种子×快照”。
- D1每快照8个目标块，共360块；D2固定使用其中前4块，共180块。
- 只使用原target development的542张图，按无标签ID分为A/B各271张；final标签不访问。
- 所有方法在同一块使用同一θ、源fit批次、query池、目标A批次；参数变化后不带入下一诊断块。
- 第一工作包新增真实数据适配作业数为0；Oracle临时一步不成为训练起点。
- GPU/CPU状态在实际执行前重新检测；本方案不是已获批的连续训练时长，也不是整份路线一次启动的指令。
