# D9：候选冻结后的完整适配与跨数据集复核

[返回实验列表](README.md#experiment-list) · [统一协议](method.md) · [执行预算与交付](execution.md)

**优先级P3；条件待执行。** 本项不是第一工作包，也不是现在就启动的全矩阵。最多两个候选通过D1与D2后，才冻结本项执行清单。

## 1. 假设与选择规则

新的读取／幅度规则，相对原v2及简单监督方式，带来可重复、具有实际幅度的分类改善，并保留真实标签对打乱／随机对照的优势。

候选只允许一个模块变化，例如简化校准、仅表示核、局部bank、门控、固定β或裁剪之一。若要组合两个改动，必须先各自通过消融，再另登记组合版本。最多保留2个候选，不能按每个迁移方向选不同方法。

候选排序：先满足D1/D2全部门槛，再按跨任务平均R_Q降序；并列差≤1e-8时优先更简单／更低成本者。这个选择使用了已观察的development诊断，必须如实说明，不能当作盲测。

## 2. 数据、共同起点和适配

| 数据 | 源角色 | 任务与开发／最终标签 |
|---|---|---|
| Mutagenicity | fit779、query196、source validation109 | 0→1/2/3；dev每域542；final仍封存 |
| PROTEINS | fit199、query51、source validation28 | 0→1/2/3；dev每域139；final139/139/140仍封存 |

使用各自既有SEGA边数域索引和角色文件，不把这些称作官方域。PROTEINS原缓存及角色对应先做哈希预检，不直接把旧v1的700步结果当新v2对照。

统一hidden32、2层、mean；Mutagenicity为14/3维GINE；PROTEINS在预检中锁定节点／边维度，有边特征用GINE、无边特征用GIN，具体encoder_spec写入manifest后才执行。输入维度不猜测，不强迫不兼容骨干。

- 所有公共fit起点方法：同一个source-fit best模型、普通SGD lr0.0003、无动量／weight decay、200步、fit16、目标16。
- query全部使用本数据集池，Mutagenicity196、PROTEINS51。局部候选若k超过51，必须在其候选合同事先规定按比例取整规则，不能看到PROTEINS分数后选k；默认取round(64/196×51)=17，且随机bank同为17。
- 源预训练100epoch、batch32、Adam0.003，由原source validation选best；Mutagenicity复用已核对的fit/full各5个模型。PROTEINS如旧模型不是这套配置，统一新训练fit/full各5个，不为某方法单独选择起点。
- 固定200步为主结果，源验证CE选点为次要结果；每10步验证、每50步存checkpoint；不能用target dev挑step。

## 3. 内部与资源基线

| 方法 | 设置与公平性 |
|---|---|
| FROZEN-FIT | 公共fit模型不更新 |
| FIT-SGD | 仅每步fit16监督 |
| FIT+QUERY-CE | 同一fit起点；g_fit16＋0.1g_query_all，query196/51每步全部真实标签 |
| FULL-SOURCE | 源训练全集重新预训练并继续监督；独立资源组，起点与训练预算不同，单独解释 |
| PSEUDO | 公共fit起点，目标batch16，阈值0.9，源CE＋0.1伪标签CE |
| KRR | D3的固定简单读取参照；主alpha0.005，若λ规范另改则提前冻结 |
| V2-ORIGINAL | 原joint0.01、HA、β0.1 |
| CANDIDATE-1/2 | 最多两个冻结候选；各保留原v2对照 |

FIT+QUERY-CE是本版必须补的强对照：它与TQG同起点、同fit/query标签访问次数，检验“直接继续使用query标签”是否已经够好。FULL-SOURCE不能替代这一对照。

所有CE均按图取平均。FULL-SOURCE后续每步从完整源训练池抽16张，仍用同一SGD学习率与200步；预训练成本单列。PSEUDO取当前目标预测的argmax作停止梯度的硬标签，仅对最大softmax概率≥0.9的图取平均CE；没有图过阈值时辅助损失为零，记录保留率。查询与损失前向遵守同一eval状态。

核心最多8个适配臂×3任务×5种子×2数据集＝240次新适配的上限；有些历史作业可在逐项审计后复用，实际新增数在manifest中列出，不能一律声称240次新训练。

每个候选另加自身的标签置乱控制和等范数同V随机反馈控制，各15次适配／数据集／候选，最多再120次；不是把旧原v2置乱行当新候选的因果控制。这里每个模型种子每类null只运行1条适配轨迹，区别于D1的3个离线重复，种子表在job_matrix中冻结。极端上限360次适配，需分包预算，默认不全启动。相同输入及拟合批次按seed隔离RNG，每个训练step只做一次参数更新。

null在各自当前θ上重算候选的TRUE反馈作为范数参考，不能借用已走到另一θ的真实标签轨迹。设q_TRUE为含β／门控／裁剪后的实际反馈向量；置乱控制把对应非零置乱向量缩放至||q_TRUE||，随机控制在同一V内取同范数随机向量，最终都执行g_S＋q_null。q_TRUE为零时保持零，不能放大；其他不可匹配情形按D0规则记NA／失败。此控制保留了真实源标签提供的幅度信息，只检验方向增量，不称“完全不用真实标签”的训练基线。

## 4. 性能与机制门槛

主指标：开发集balanced accuracy（%），5模型种子均值±样本SD、配对差／胜平负。次要：普通CE、AUROC、类别召回／混淆矩阵、训练时间、峰值内存、非零反馈率、收敛与回退。

一个候选获得“完整实验支持”须同时：
1. Mutagenicity至少2/3任务相对原v2平均BA提升≥0.5个百分点，且各至少3/5种子为正；
2. PROTEINS至少2/3任务方向同向、均值提升≥0.5个百分点且各至少3/5种子为正；
3. 两数据集各自跨任务平均BA不低于FIT+QUERY-CE、KRR及同起点FIT-SGD；FULL-SOURCE另列，不隐去不利结果；
4. 相对自身置乱／随机控制，至少2/3任务有平均正增益及≥3/5种子为正；
5. 真实梯度的离线诊断优势保留；工程／标签权限全通过。

这组0.5pp是本次提出的实用性筛选目标，不是保证能取得、也不是统计显著性。置信区间、全部任务与CE都同时报告；不把多个微小正数拼成成功。满足不了时可以报告机制成立但性能弱，不能调低阈值。

固定200步不是等算力。若要主张效率，另在同硬件做预定墙钟预算曲线：每方法每作业固定600秒适配、最大2000步，只在完整一步边界停止，排除预训练并另外报告其成本；只保存预算内last，源验证按固定规则另列。此项另登记，不与固定步数表混合排名，不属于上面360次上限。

## 5. 投稿前还缺什么

本项内部复核通过不等于满足ICML投稿要求。投稿级实验仍需：
- 在执行时重新核对近24个月的图级闭集GDA方法，不用只做节点分类或开集的方法冒充直接同任务SOTA。
- 至少落实两个接近的近期机制参照，例如[RaT](https://arxiv.org/abs/2603.25466)与[TILT](https://arxiv.org/abs/2605.14280)。图适配版本要明确标成改编；若只实现残差KRR更新，不能命名为原论文完整RaT。
- 官方原协议复现与图级改编分开；未取得公开原协议数值、未验证实现时写“待复现”，不编expected_metric或强行设20%窗口。
- 如果要主张真实领域变化而非图规模迁移，另冻结具有自然域／不同变化类型的数据集协议；不能只靠两个规模域基准普遍化。
- 所有超参搜索给基线同等预算。最终标签一次性评价需新协议，本项不触发。
