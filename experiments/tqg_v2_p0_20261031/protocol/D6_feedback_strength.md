# D6：反馈权重、更新幅度与只缩小不放大的裁剪

[返回实验列表](README.md#experiment-list) · [统一协议](method.md) · 依赖：[D1](D1_gradient_quality.md)、[D2](D2_one_step.md)

**优先级P2；条件待执行；新增训练0。**

白话：先确认建议方向有价值，再检查是不是走得太轻或太重。放大一个错误方向不会使它变正确。

## 1. 固定设计

使用D2的180块；θ、源fit16、query196、目标A16、B271、核／W和未加权梯度都不变。每块复用同一个g_hat，不为不同β重算查询。

- 固定β∈{0,0.03,0.1,0.3,1.0}。
- η∈{0.0001,0.0003,0.001}，主η仍为0.0003。
- β0.1另加一个CAP臂，κ=0.3；只改变幅度规则。
- 主分析基于当前joint0.01／h+A；若换D3/4得到的候选，必须使用新candidate_id并重做同样对照。

## 2. CAP的精确定义与边界

当||g_S||₂>1e-12且||g_hat||₂>1e-12时：
a_cap=min(1, κ||g_S||₂/(0.1||g_hat||₂))，
d_CAP=g_S+0.1a_cap g_hat。

g_hat近零：保持零反馈。g_S近零：关闭本次裁剪，保留原β0.1并记录reference_unavailable；不因源已驻点而自动取消目标反馈。

它保证正常参考情形下反馈不超过当前源梯度范数的0.3倍，且绝不放大小反馈。源梯度虽非零但很小时仍可能过度压制，因此不能先验认定CAP更安全。加入CAP接口时补做D0的源梯度为零边界；D8另记录近零参考下的表现，不假定200步warmup就已到驻点。

不执行beta_t∝||g_S||/||g_hat||的无上限放大。也不使用目标标签决定每块β或是否关闭。

## 3. 指标、规模与预设门槛

5个固定β＋1个CAP，3个η，180块：最多3240个一步更新；与D2重复的结果按哈希复用，不冒充新训练。

报告每个β的R_Q、相对冻结与源SGD的CE变化、A/B差异、有害更新率、反馈／源梯度比及参数增量。β>0的纯反馈夹角不因正标量改变，不能把性能变化说成方向估计更准确。

“有害”指CE_B比匹配源SGD高超过1e-8；另外报告连续改变量，不能只依赖这个阈值。CAP报告裁剪比例、裁剪因子分布和近零参考比例。

固定β候选须达到D2同样的R_Q≥1e-4、至少2/3任务且各至少3/5种子为正；等范数真实标签对null的优势仍须存在。CAP须相对未裁剪β0.1平均B池效果不下降、有害率减少≥10个百分点，至少2/3任务满足。

选择新β时，只允许一个全局值，不能按任务挑最优值。预定选择规则：在满足门槛的值中，取跨任务平均R_Q最大的β；并列（差≤1e-8）取最接近0.1者，仍并列取较小者。这是development-informed研究选择，必须披露；不能称完全不依赖目标开发标签的超参选择。

## 4. 决策

- 所有正β都比β0差，Oracle却有效：回到估计器，暂停权重调优。
- 仅大β有改善：验证不是随机／打乱放大后同样有效，再登记新候选。
- 仅极窄的β或η组合有收益：判为敏感，不进入D9主候选。
- CAP从未触发：它没有实际贡献，不把它写成有效模块。
- CAP只靠接近全关闭变好：与零反馈比较，不把“回到源SGD”说成成功适配。

输出beta_grid.csv、cap_events.jsonl、beta_seed_summary.csv、β—CE曲线及decision.md。只有冻结候选通过D1及按新candidate_id登记的D2后才进入完整训练。
