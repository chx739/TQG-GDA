# Mutagenicity：SEGA骨干与预训练配置下的TQG实验

采用原SEGA边数域索引，GINE（14维节点标签、3维边标签）、hidden32、2层、mean readout、float64。源预训练100 epoch、batch32、lr0.003；TQG200 step、Adam lr0.0003、K4、rho0.05、ridge0.01、反馈权重0.1。

源域1084张：975训练＝779 fit＋196 query，109验证。全源查询为975张，包含预训练使用的779张fit，因此不只是增加样本数。B_full有自己的全源预训练起点。

**SEGA配置边界：**包中没有Mutagenicity专用训练配置；本轮沿用通用源配置和域索引，使用TQG机制替代SEGA几何/OT模块。适配200步为用户确认的TQG预算，未采用SEGA两轮开发示例。100 epoch在fit/all-source分别为2500/3100次更新，不沿用PROTEINS的700步预算。

## 证据范围

本轮105次适配、10次源预训练、15个冻结参考；225次开发集评价。每个目标域开发集542张；final分别542/542/543张，仅输入用于无标签transductive适配，final标签未评价。源验证用于选模，目标开发指标在全矩阵训练封存后才读取，未据此调参。

相同100 epoch不等于相同更新次数；源图规模、预训练和GINE与此前PROTEINS实验不同，不能将跨数据集差异单独归因于样本量。未复现SEGA方法本身、外部强基线或匹配墙钟预算。五种子探索性结果不代表统计显著或方法普遍有效。


## 执行记录与偏差

- 全源监督预训练最初继承了TQG方法标记，被源查询隔离校验在训练开始前拒绝。提交b59cbd7将其正确标记为source_only；训练数值模块未改动。此前完成的两个fit源模型（seed3405/3406，提交68bb171）经文件哈希校验后复用，其余源训练与适配使用b59cbd7。
- 执行最初使用2个单线程进程，之后改为每种子一个进程，共5个；每进程仍为1线程。冻结配置文件、学习率、数据划分、采样和探测随机数未变。execution_override.json保留此执行方式调整。
- 为降低SATA写入开销，运行文件临时写入本机NVMe。两个0→1的全源odd作业从已保存的模型、Adam和RNG状态恢复，results.csv的event_flags记为restart。实际step100 checkpoint重算的step101记录与原日志完全相同（不比较墙钟时间和独立选模记录）。runtime_restart_check.json保留证据。
- 训练和评价完成后，所有NVMe输出逐文件SHA256校验并恢复到正式/home路径。临时副本与重启前存储副本保留作备份。不同存储阶段的耗时不用于方法速度优劣比较。
- NaN/Inf检查一直开启，未静默改变预算或超参数。debug_events.jsonl记录配置错误与修复。代码库和原始缓存均保留所有标签，但训练的目标输入视图不暴露y；目标final标签未用于训练、选择或评价。
- 使用现有TQG环境Python3.12.4、PyTorch2.5.1、PyG2.6.1、NumPy1.26.4，具体见runtime_versions.json。这是SEGA骨干与源训练超参数的适配，不是原包Python/CUDA环境或SEGA方法本身的逐位复现。
- 本轮未在Mutagenicity补跑随机方向、源方向、局部匹配或投影反馈；不能仅凭这里的分类结果证明目标方向优于这些对照，也不能将与PROTEINS的差异单独归因于数据量。

## 本轮结论

- 固定200步时，TQG没有跨三个方向的稳定优势，四个TQG设置的平均balanced accuracy均未超过对应方向的全源监督基线。全源基线有独立的975图源预训练起点，不能把其差异单独归因于TQG反馈。
- query196＋odd在0→3比继续fit监督高0.56个百分点，五个种子4胜1负；在0→1/0→2分别低0.11/0.33个百分点。query196＋odd+even在0→3高0.43个百分点，同为4胜1负，但其他两个方向仍略低。
- 扩大至975张源图后，分类结果更接近继续fit监督，增量很小；even的增量方向不一致，没有稳定收益。
- 更大数据集下仍未获得稳定优势，但本轮也改变了骨干和源预训练更新预算，不能据此识别纯粹的样本量因果作用。
