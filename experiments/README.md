## 阶段总结

研究目标是利用无标签目标图表示的密度结构，调整源分类器的决策边界。当前已完成合成机制实验、P0，以及真实图 R1–R6；证据分为以下三个阶段。

| 阶段 | 完成的工作 | 核心发现 |
|---|---|---|
| 合成实验与 P0 | 验证边界几何；拆解总体/经验/学习 score、源拟合、样本量、带宽和训练预算 | 正确密度请求在受控条件下有小幅任务收益；源过拟合可抵消收益。二维长预算能学到方向，但不等于真实图分类有效 |
| R1–R3 | 检查冻结表示、局部密度支持、score 预算、多轮适配及源风险/置信度约束 | 表示保留类信息，但边界局部支持不足；增加预算和请求强度没有解决平均 NLL 退化，约束改善 NLL 也不保证分类改善 |
| R4–R6 | 扩展到全方向和三种数据设置，再分解源驱动与密度请求 | 当前 score 未建立稳定额外分类收益；局部去掉源梯度后，请求仍无平均 NLL 收益，源驱动造成更大的目标 NLL 代价 |

**当前判断：**现有结果不支持原样扩展“当前表示＋score＋更新规则”的组合。后续优先分别验证请求的任务相关性与跨样本支持，以及持续源驱动的泛化代价。这里没有证明所有低密度分隔都无效，也没有直接证明神经 score 被生成图主导；KDE 自贡献只是诊断线索。

## 最新完成：R6 机制分解

[R6｜源梯度与密度请求分别如何影响泛化？](mutagenicity/r6_源梯度与密度请求分解_20261114/README.md)：三个设置均已完成 R6_FINAL 封存。复用 R5 固定状态，比较六组候选与三个步长，不新增模型训练或闭环适配。

- Mutagenicity 两种划分中，纯密度请求在首尾时点均平均增加目标 NLL；减半、四分之一步长没有改变该符号。首个时点的有限步长交互很小，不支持将失败主要归因于源驱动掩盖或步长过大。
- 源驱动的目标 NLL 代价更大，但不能全部解释成普通源过拟合：部分局部比较中，源验证改善而目标恶化。
- 共 348/360 个状态块可评价；PROTEINS 每个时点为 54/60，完整五种子全方向均值保留 NA。完成状态与证据位置见 [R6 结果摘要](mutagenicity/r6_源梯度与密度请求分解_20261114/README.md#结果摘要)。

这些是固定状态的局部机制证据，尚未证明关闭源梯度或反向请求的完整适配轨迹有效。

## 整体效果：R5 三设置验证

[R5 总报告](mutagenicity/r5_原始方法与请求价值_20261114/report.md)覆盖每个设置 12 方向、5 种子。B0 为源模型，B1 为保留源拟合与响应矩阵的零请求对照，A0 为原始 TSBA。下表差值单位为百分点。

| 设置 | A0−B0 Accuracy | A0−B1 Accuracy：score 额外贡献 |
|---|---:|---:|
| Mutagenicity 边数 | +0.34283 | -0.01844 |
| Mutagenicity 节点数 | +0.22594 | -0.00154 |
| PROTEINS 边数 | -0.16739 | +0.01199 |

Mutagenicity 的小幅收益无需 score 也能获得；PROTEINS 整体退化，score 未显示稳定额外收益。三设置目标 NLL 均恶化，大部分退化在零请求对照中已经出现。共 360 条轨迹、10,800 次尝试，其中 120 条/3,600 次复用 R4，不计为独立重复实验。

## 结论边界

- 合成 oracle 机制、工程正确性和真实图效果分别报告；[P0](synthetic_data/p0_分数训练预算_20261110/report.md) 的 99.980% 是二维固定查询的方向指标，不是图分类 Accuracy。
- 完整目标域上的结果属于传导式开发评价，不是独立最终测试；R5/R6 的目标标签或梯度用于封存后的评价与诊断，不进入无监督适配。
- Mutagenicity 两种划分高度重合；五个 seed 描述训练随机性，12 个方向共享图和源模型，不能视为独立域样本。
- R1–R2 与后续轮次的数据池和选模口径不同，不直接用跨轮绝对分数判断方法改进。

## 实验项目结构

```text
experiments/
  common/                  # 纯通用工具
  synthetic_data/<experiment_id>/
  mutagenicity/<experiment_id>/
    README.md              # 问题、结论、运行方式、依赖
    src/                   # 该轮实现
    scripts/               # 该轮启动与分析入口
    configs/               # 计划与实际配置
    docs/                  # 方案及补充说明
    results/               # 汇总、图表、日志、核验
    report.md              # 完整结论
scripts/                   # 通用 TSBA 入口与仓库工具
```

实验目录采用「编号_中文主题_日期」，索引采用「编号｜研究问题」。新实验可参考[模板](templates/README.md)。

新增文件前先阅读本页、所属数据集 README 和模板，确定所属轮次，再按以下规则落位：

- **方案属于轮次目录。** 协议与补充说明放在该轮 `docs/`，计划与实际配置放在 `configs/`。即使尚未实现代码、仅有实验计划，也使用这一结构；不要在 `experiments/` 或数据集根目录单独新建轮次协议。
- **跨数据集仍可属于同一轮。** 沿用已确定的主数据集目录，将同轮所有数据集的协议、配置和结果统一归档，并在轮次 README 中列明范围。不要仅因增加验证数据集而另建并列轮次或把共享协议提到根目录。
- **先归档，后更新导航。** 总索引链接数据集或轮次入口，各轮 README 链接自己的方案与配置。检查时同时核验目录归属与链接有效性，不能修改目录规则来迁就错误位置。

例如，R5 的 Mutagenicity 两种划分与 PROTEINS 验证统一放在 Mutagenicity 目录：

```text
experiments/mutagenicity/r5_原始方法与请求价值_20261114/
  README.md
  docs/r5-protocol.md
  configs/mutagenicity-plan.json
  configs/proteins-plan.json
```

该示例为计划阶段；实现与运行后再增加本轮 `src/`、`scripts/`、`results/` 和 `report.md`，不提前生成虚构的执行记录。

`common` 不按轮次命名，不保存训练或适配流程。R2/R3 等特定协议的代码归本轮 `src/`；后续实验沿用时明确列出依赖。核心算法仍位于 `tsba/`。

## 运行代码

从仓库根目录安装并调用模块入口：

```sh
python -m pip install -e '.[experiments]'
python -m experiments.mutagenicity.r4_全方向迁移对照_20261112.scripts.run --help
python -m experiments.synthetic_data.p0_分数训练预算_20261110.scripts.run_p0 --help
```

各轮 README 列出具体入口。命令参数与标签使用规则仍以该轮协议为准；目录整理不授权重跑真实实验。研究入口面向仓库 checkout，使用 editable 安装；历史数据、封存配置和外部档案不会随 Python 包安装自动提供。
